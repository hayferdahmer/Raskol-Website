# Web API Bridge — архитектура публичного портала

**Статус:** проектирование, не подключено к игровому серверу  
**Версия контракта:** v1  
**Целевая платформа сервера:** Paper 26.2 · Java 25

## Назначение

Web API Bridge — отдельный серверный сервис между плагинами RASKOL и публичным сайтом. Он публикует только проверенные данные, которые нужны порталу: состояние сервера, агрегированный онлайн, публичные события, сводки миров и рейтинги.

GitHub Pages остаётся статическим фронтендом. Нельзя помещать API-секреты, токены Discord, ключи плагинов или административные endpoints в HTML, JavaScript, JSON-файлы репозитория либо браузерное хранилище.

## Границы доверия

1. **Игровой сервер и плагины** — источник истины. Bridge не изменяет игровой мир и не исполняет команды.
2. **Private ingestion** — закрытый канал от сервера к Bridge. Аутентификация по отдельному ротируемому секрету или mTLS; секрет хранится только в переменных окружения/secret manager.
3. **Public API** — read-only HTTPS API. Только allowlist полей и заранее определённые запросы.
4. **Сайт** — недоверенный публичный клиент. Любое значение из браузера считается изменяемым пользователем.

Bridge не должен иметь доступа к консоли сервера, файловой системе миров, RCON или произвольному выполнению команд.

## Публичный контракт v1

Базовый путь: `/api/v1`.

| Endpoint | Назначение | Кэш |
|---|---|---:|
| `GET /status` | online, players.online/max, версия, время последнего обновления | 10–20 с |
| `GET /worlds` | публичные названия миров и их доступность | 60 с |
| `GET /events` | опубликованные события и объявления | 60–300 с |
| `GET /leaderboards/{board}` | разрешённые рейтинги | 60–300 с |
| `GET /players/{publicId}` | только добровольно публичный профиль | 30–60 с |

Контрактные примеры и обязательные поля находятся в `docs/contracts/public-api-v1.json`.

### Политика публичных данных

- Статус: только агрегированные числа и публичная версия Minecraft.
- Игроки: публичный профиль появляется только после явного согласия владельца аккаунта.
- Идентификаторы: публичный случайный ID, не UUID и не внутренний идентификатор аккаунта.
- Рейтинги: только поля, разрешённые отдельной политикой публикации.
- События: только прошедшие редакционную проверку публикации.
- Не публиковать IP, hostname, адреса backend-узлов, UUID, IP игроков, координаты игроков, инвентарь, приватные сообщения, права, группы, токены и технические stack traces.

Игровые адреса подключения остаются только такими: Anycast `raskolpro.play.ski` и SRV `raskol.play.ski`. Адреса API и карты — отдельные домены; до их настройки ссылки не показываются.

## Безопасность и эксплуатация

- Только HTTPS; HSTS на публичном домене.
- Allowlist маршрутов и полей; неизвестные поля не сериализуются.
- Rate limiting по IP/ключу, ограничение размера ответа и pagination caps.
- CORS только для точного домена сайта; CORS не считается аутентификацией.
- Таймауты, circuit breaker и кэш последнего корректного ответа.
- `updatedAt` и `stale` в статусе позволяют UI отличить недоступность от нулевого онлайна.
- Валидация входящих payloads, лимит частоты ingestion, защита от replay (timestamp + nonce).
- Логи аудита без секретов и персональных данных.
- Секреты ротируются; при утечке ingestion отключается до ротации.
- Ошибки API не раскрывают внутренние адреса, пути, названия классов и stack traces.

## Состояния UI

- `online`: сервер подтвердил доступность.
- `offline`: подтверждённый статус недоступности.
- `stale`: последнее корректное состояние старше допустимого окна.
- `unknown`: источник ещё не подключён или не дал ни одного корректного ответа.

Нельзя подменять `unknown` нулевым онлайном или показывать «сервер офлайн» при отсутствии API.

## Интеграция плагинов

- **BlueMap** — отдельная публикация карты через собственный HTTPS-домен и reverse proxy. Не проксировать административные endpoints и не встраивать приватный адрес.
- **Plan** — внутренний инструмент аналитики для команды. Публичный сайт не должен встраивать staff dashboard.
- **DiscordSRV** — связка игровых и Discord-аккаунтов через одноразовый код, созданный в игре. Никогда не просить пароль Microsoft/Discord на сайте.
- Собственные плагины RASKOL передают события через узкий адаптер/DTO, а не напрямую в публичный API.

## Порядок реализации

1. Развернуть Bridge вне GitHub Pages и настроить HTTPS + secrets.
2. Реализовать private ingestion и схему валидации.
3. Реализовать только `GET /status`, покрыть unit/integration tests.
4. Подключить сайт к статусу; корректно обработать loading/unknown/stale/error.
5. Добавить worlds/events/leaderboards после согласования их источников.
6. Добавлять профили только после проектирования consent, удаления и приватности.

## Критерии готовности

- В собранном фронтенде нет секретов и внутренних адресов.
- Публичные endpoints read-only и соответствуют allowlist.
- При отключении Bridge сайт не ломается и не показывает ложные данные.
- Тесты проверяют валидацию, rate limit, stale cache, отказ ingestion и отсутствие приватных полей.
- Реальные адреса карты/API публикуются только после настройки DNS, HTTPS и проверки доступа.

**Важно:** этот документ фиксирует архитектуру. Он не означает, что API, BlueMap, Plan или DiscordSRV уже установлены либо подключены на production-сервере.
